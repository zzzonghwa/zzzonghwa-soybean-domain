## 문제 정의

[[뉴스 데이터 수집 아키텍처]]가 "뉴스를 어떻게 모으는가"를 다뤘다면, 이 노트는 <mark style="background: #FFF3A3A6;">"모은 뉴스를 어떻게 점수화해서 가격 예측 모델의 입력으로 만드는가"</mark>를 다룬다.

## 5가지 핵심 설계 결정

### 결정 1. 산출물을 3가지 차원으로 분리

단일 감성 점수로는 "평상시 분위기"와 "WASDE 서프라이즈 충격"을 구분할 수 없다.

| 차원 | 역할 | 예시 피처 |
|------|------|-----------|
| 감성 인덱스 | 시장 분위기 | `news_sentiment_ewma_7d` |
| 이벤트 임팩트 | 구조적 사건 충격 | `news_event_impact_score` |
| 주목도/볼륨 | 정보 흐름 강도 | `news_volume_zscore_20d` |

> [!NOTE] 왜 분리하는가
> RavenPack과 Thomson Reuters MarketPsych(TRMI)도 감성/이벤트/주목도를 별개 컬럼으로 제공한다. "기사는 적지만 강한 bearish 시그널"과 "많은 기사지만 중립"을 구분하기 위함이다.

### 결정 2. Bullish/Bearish 재라벨링 (범용 FinBERT 한계 극복)

FinBERT는 "Record harvest in Brazil"을 positive로 분류하는데, 이는 **틀리지 않다**. 하지만 대두유 가격에는 **bearish**다. → [[커머디티 뉴스 감성의 역방향 문제]]

<mark style="background: #FFF3A3A6;">도메인 특화 파인튜닝 없이는 모델이 역전 관계를 학습하지 못한다.</mark>

### 결정 3. 임팩트 스코어 = 4요소의 곱

```
Impact_Score = Sentiment × Source_Weight × Novelty × Market_Attention
```

| 요소 | 의미 | 왜 필요한가 |
|------|------|-------------|
| Sentiment | FinBERT 방향성 [-1, +1] | 기본 신호 |
| Source_Weight | 소스 등급 가중치 (0.3 ~ 1.5) | Reuters 단독 속보 ≠ 블로그 기사 |
| Novelty | `1 / log(1 + 7일 토픽 수)` | 20번째 가뭄 기사의 영향력 감쇠 |
| Market_Attention | CFTC 미결제약정 변동률 | 시장 참여자 활성 시기에 반응 증폭 |

**Source_Weight 등급**
- Tier 1 (USDA, CFTC): 1.5
- Tier 2 (Reuters, Bloomberg): 1.2
- Tier 3 (Fastmarkets, Oil World): 1.0
- Tier 4 (일반 언론): 0.7
- Tier 5 (블로그/SNS): 0.3

### 결정 4. 집계는 3가지 차원으로 분리

기사 단위 스코어를 일별 피처로 합칠 때 **시간/볼륨/강도**를 분리해서 다룬다.

**방법 A. EWMA (지수가중이동평균)** — 감성 추세
```
α = 2/(N+1), N=7 → α=0.25
```
> [!WARNING] 반감기 주의
> α=0.25의 실질 반감기는 약 **2.4일** (7일 아님). "7일 반감기"를 원한다면 α≈0.095를 써야 한다. N=7은 기간 파라미터일 뿐 반감기와 다른 개념.

**방법 B. 이벤트 충격 감쇠 함수** — WASDE 등 이벤트
```
event_impact(t+k) = EventScore(t) × exp(-λ × k)
λ = 0.3 → 반감기 ln(2)/0.3 ≈ 2.3일
```
선형 감쇠는 비현실적. 큰 이벤트는 **초기에 강하게 반응 후 빠르게 소화**되므로 지수 감쇠가 자연스럽다.

**방법 C. 토픽별 볼륨 비율 편차** — 주목도
```
news_attention_brazil_7d = 최근 7일 브라질 비율 - 90일 평균 비율
```
절대 기사 수는 수집 소스가 늘어나면 구조적으로 증가한다. **비율 편차는 수집 규모 변화에 robust**.

### 결정 5. 데이터 누수를 설계 단계에 명시

뉴스 피처의 데이터 누수는 코드 실수가 아니라 **설계 결함**이다.

> [!WARNING] 대표적 누수 사례
> - EWMA를 전체 기간으로 계산 후 슬라이싱 → 미래 정보 포함
> - 미래 가격을 보고 라벨링 ("3% 올랐으니 bullish") → 가격 정보가 라벨에 스며듦
> - 무작위 train/val split → 시계열 자기상관으로 누수 발생 → **Time-based Split 필수**

## 실무 설계 패턴

### RavenPack과의 매핑

| RavenPack | 우리 설계 |
|-----------|-----------|
| `ess_score` (Event Sentiment Score) | `Sentiment × Source_Weight` |
| `novelty_score` | `Novelty_Factor` |
| `relevance_score` | 2단계 관련성 필터링 |

### 학습 데이터 부족 시 해법

| 상황 | 해법 |
|------|------|
| 라벨 없음 | Weak Supervision + 규칙 기반 |
| < 200건 | Few-shot LLM 라벨링 (ICR > 0.7 검증) |
| 200~2,000건 | FinBERT 파인튜닝 + Class imbalance 처리 |
| > 2,000건 | 완전 지도학습 + Time-based Split |

> [!NOTE] ICR
> Inter-Coder Reliability. 복수의 라벨러가 같은 기사를 독립 분류했을 때 일치도. 0.7 이상이면 신뢰 가능한 라벨.

# LLM 기반 뉴스 감성분석 파이프라인
## 왜 LLM인가

| 항목     | 사전 기반 | FinBERT        | LLM        |
| ------ | ----- | -------------- | ---------- |
| 문맥 이해  | ✗     | ○              | ◎          |
| 도메인 지식 | 수동 구축 | fine-tuning 필요 | **사전 내장**  |
| 추론 근거  | 없음    | 제한적            | **자연어 설명** |
| 비용     | 매우 저렴 | 저렴             | 비쌈         |
| 속도     | 매우 빠름 | 빠름             | 느림         |

<mark style="background: #FFF3A3A6;">도메인 특화는 필요한데 학습 데이터가 부족한 대두유 도메인에 LLM이 적합하다.</mark>
## 전체 아키텍처

```
수집기 → 전처리/필터 → 큐(Redis/SQS) → LLM 스코러
  → 검증/후처리 → 집계/피처화 → master_daily
```

## 1단계: 수집기

### 필수 메타데이터
- url (UNIQUE)
- source, published_at (UTC), collected_at
- title, body, language, raw_hash

### 1차 필터링 (LLM 호출 전)

> [!NOTE] 비용 절감의 핵심
> LLM 호출 전 필터링으로 전체 뉴스의 90% 이상이 걸러지는 것이 정상.

- 키워드 필터: soybean, soyoil, palm oil, biodiesel, CBOT, WASDE, NOPA
- 언어 필터, 중복 제거(URL + 본문 해시)
- 제목 유사도 클러스터링 (같은 이벤트 기사는 대표 1건만)

## 2단계: 프롬프트 설계

### 좋은 스코어링 프롬프트 4요소
1. **역할 정의** ("너는 대두유 시장 애널리스트다")
2. **도메인 컨텍스트** (가격 결정 요인 요약)
3. **출력 스키마** (JSON 구조 명시)
4. **Few-shot 예시** (2~3개의 라벨링 예시)

### 핵심 포인트
> [!WARNING] 도메인 트랩 명시 필수
> "대두 풍작은 대두유 가격에 부정"처럼 역직관 케이스를 예시로 박아야 함.

- JSON Schema 강제 (OpenAI `response_format`, Claude tool use)
- Chain-of-Thought 비활성화 (짧고 일관된 출력)
- Few-shot 3~5개가 최적

## 3단계: LLM 스코러

### 모델 선택

| 모델 | 용도 |
|------|------|
| Haiku / GPT-4o-mini | **대량 배치 처리** |
| Sonnet / GPT-4o | 주력 운영 |
| Opus / GPT-4 | 골드 라벨 생성, 검증 |

<mark style="background: #FFF3A3A6;">실무 패턴: Haiku로 대량 스코어링 → Opus로 샘플 검증</mark>

### 배치 처리 고려사항
- Rate limiting (TPM/RPM 준수)
- 재시도 로직 (지수 백오프, 최대 3회)
- 오류 격리 (한 건 실패가 전체 배치를 망치지 않게)
- 비용 모니터링

### 캐싱 전략
- URL 해시 기반 캐싱
- `prompt_version` 필드로 프롬프트 버전 관리
- LLM 응답 원본(raw) 영속화 → 재계산·감사 가능

## 4단계: 검증 및 후처리

> [!NOTE] 신뢰하되 검증
> LLM 출력은 Pydantic 스키마로 범위 검증, 타입 검증 필수.

### 이상치 탐지
- |sentiment| > 0.9 AND impact > 0.9 → 사람 검토
- 일별 평균 급변 → 프롬프트/모델 이슈 가능성
- 같은 뉴스 2회 돌려 분산 체크 (temperature 이슈)

### 골드 라벨 데이터셋
- 100~300건 전문가 직접 라벨링
- LLM 스코어 일치율 벤치마크
- 프롬프트 개선 시 회귀 검증

## 6단계: 운영 모니터링

| 지표 | 목적 |
|------|------|
| 일일 수집량 | 수집기 장애 감지 |
| LLM 성공률 | API 안정성 |
| 토큰 사용량 | 예산 관리 |
| 스코어 분포 | 드리프트 감지 |
| 골드셋 일치율 | 품질 유지 |

## 비용 추정 (참고)
가정: 일일 500건 스코어링, 1000 토큰/건 = 50만 토큰/일

| 모델 | 월 비용 |
|------|---------|
| Haiku/4o-mini | ~$5 |
| Sonnet/4o | ~$45 |
| Opus/GPT-4 | ~$225 |

## 구축 로드맵
1. **Phase 1 (PoC)**: 매체 3~5개, LLM 단일 호출, 골드셋 100건, 감성 피처 1개
2. **Phase 2 (검증)**: 상관 분석, 성능 기여도, 프롬프트 튜닝
3. **Phase 3 (운영화)**: 배치·캐싱·모니터링, 다중 카테고리 확장

## 주의 및 한계

> [!WARNING] LLM 환각과 편향
> - 반드시 `reasoning` 필드 저장 → 추적 가능
> - 특정 국가/관점 편향 가능 → 골드셋 주기 검증
> - temperature=0 권장
> - 프롬프트 주입 방지: 뉴스 본문을 구분자로 감싸기
> - **시점 누수**: LLM 학습 cutoff 이후 데이터로 백테스트해야 미래 정보 누수 방지

# 뉴스 감성지수 작성 방법론

## 왜 필요한가
뉴스 감성지수(News Sentiment Score)는 시장 참여자들이 뉴스를 통해 형성하는 **심리와 기대**를 정량화한 지표다. 대두유처럼 수급 뉴스·정책·기상 이벤트에 민감한 원자재에서는 <mark style="background: #FFF3A3A6;">가격 선행 지표로 작동할 수 있다</mark>.

## 전체 5단계
```
수집 → 스코어링 → 점수 구조화 → 일별 집계 → 모델 피처화
```

## 1단계: 수집
### 주요 소스

| 소스                    | 특징         | 중요도 |
| --------------------- | ---------- | --- |
| Reuters Commodities   | 원자재 전문, 속보 | ★★★ |
| Bloomberg Agriculture | 심층 분석      | ★★★ |
| USDA / WASDE          | 공식 수급 발표   | ★★★ |
| Oilseed & Grain News  | 유지작물 특화    | ★★  |
| 브라질 매체 (Agrolink 등)   | 남미 공급측     | ★★  |
| 중국 업계지 (Cngrain 등)    | 수요국 동향     | ★★  |

### 수집 방법
- RSS 피드, 뉴스 API (NewsAPI, GDELT, Event Registry)
- 웹 스크래핑, 공공 데이터(USDA, CFTC)

> [!WARNING] 반드시 기록할 것
> 발행 시각(타임존 포함), 원문 URL(UNIQUE 키), 본문 해시. 타임존 누락이 look-ahead bias의 최대 원인.

## 2단계: 감성 분석 접근법 3가지

| 방법                   | 장점                | 단점                 |
| -------------------- | ----------------- | ------------------ |
| **사전 기반** (Lexicon)  | 빠름, 해석 가능         | 문맥 미파악             |
| **ML/딥러닝** (FinBERT) | 문맥 이해             | 도메인 fine-tuning 필요 |
| **LLM 기반**           | 도메인 지식 내장, 구조화 출력 | 비용, 속도             |

> [!NOTE] 실무 선택
> 초기 프로토타입은 **LLM 기반**이 빠르다. 대량 과거 데이터는 FinBERT, 실시간 운영은 사전 기반 + LLM 하이브리드.

## 3단계: 점수 구조 (DB 스키마 기준)

| 컬럼 | 범위 | 의미 |
|------|------|------|
| sentiment_score | -1 ~ +1 | 가격 방향성 |
| impact_score | 0 ~ 1 | 영향 강도 |
| certainty_factor | 0 ~ 1 | 판단 확실성 |
| weight | 0 ~ 1 | 소스 신뢰도 |
| final_score | -1 ~ +1 | 최종 점수 |

<mark style="background: #FFF3A3A6;">final_score = sentiment × impact × certainty × weight</mark>

이 구조는 노이즈 뉴스와 시그널 뉴스를 자동으로 구분하는 효과가 있다.

## 4단계: 일별 집계

기본: `일별 감성 = Σ(final_score) / 건수`

고도화:
- 시간 가중 평균 (장 마감 직전 뉴스에 더 큰 가중치)
- 극단값 집계 (당일 max/min)
- 볼륨 피처 (당일 건수 = 시장 관심도)
- 카테고리별 분리 (수급/정책/기상)

## 5단계: 모델 피처화

| 파생 피처 | 의미 |
|-----------|------|
| 당일 감성 | 현재 분위기 |
| Δ 감성 | 분위기 전환 |
| MA(3/7/14) | 추세적 분위기 |
| Z-score | 이상 수준 |
| 극단값 플래그 | 뉴스 쇼크 |
| lag 피처 | 시차 반영 |

`master_daily` 테이블에 **date 키로 조인**하여 모델 입력으로 사용.

## 실무 함정

> [!WARNING] Look-ahead Bias
> 장 마감(CBOT 기준 14:20 CT, 한국시간 다음날 새벽 04:20) 이후 뉴스는 반드시 **다음 거래일 피처**로 배정. UTC 통일 후 처리 권장.

> [!WARNING] 도메인 역직관 (Reverse Sentiment Problem)
> "대두 풍작 전망"은 일반 감성으로는 긍정이지만 <mark style="background: #FFF3A3A6;">대두유 가격 관점에서는 부정</mark>(공급↑ → 가격↓). 범용 감성 모델(VADER, 일반 BERT)을 그대로 쓰면 **부호가 반대로 뒤집히는** 체계적 오류가 발생한다.

### 역방향 문제의 대표 사례

| 뉴스 문구 | 일반 감성 | 대두유 가격 관점 |
|----------|----------|------------------|
| "Record soybean harvest in Brazil" | 긍정 | **부정** (공급 과잉) |
| "Drought devastates Argentine soy belt" | 부정 | **긍정** (공급 부족) |
| "China cancels US soybean orders" | 부정 | **부정** (수요 감소, 일치) |
| "Indonesia bans palm oil exports" | 부정 | **강한 긍정** (대체재 품귀) |
| "EPA cuts biodiesel mandate" | 부정 | **부정** (대두유 수요↓, 일치) |
| "Bumper US corn crop expected" | 긍정 | **부정** (작물 회전 영향: 옥수수 경작지 확대 → 다음 시즌 대두 경작지 축소 압력, 반대 시 공급 완화) |

핵심은 "가격에 대한 영향"과 "일반적 긍·부정"이 **공급 측 뉴스**에서 자주 어긋난다는 점이다.

### 구체적 해결 방안 (5가지)

#### 1. 라벨 정의를 "가격 영향"으로 명시

```
❌ "이 뉴스는 긍정적인가 부정적인가?"
✅ "이 뉴스는 대두유 선물 가격을 상승/하락시킬 것인가?"
```

프롬프트·라벨링 가이드·학습 데이터 전부에 **"가격 영향(price impact)"** 이라는 단어를 못박는다.

> [!NOTE] 스키마 해석 주의
> 3단계의 DB 컬럼 `sentiment_score`는 **기존 스키마의 물리적 이름**이며, 의미는 "가격 영향 스코어(price impact)"로 해석해야 한다. 새 파이프라인을 설계할 때는 혼동을 막기 위해 논리적으로 `price_impact_score`로 취급하고, 신규 테이블에서는 이 이름을 쓰는 것을 권장한다. 기존 `raw_news_scored` 테이블은 호환성을 위해 컬럼명을 유지하되, 데이터 사전에 "sentiment_score = price impact on soyoil futures"라고 명시한다.

#### 2. 카테고리 기반 부호 반전 규칙 (Rule Layer)

뉴스를 먼저 **카테고리 분류**한 뒤, 공급 측 뉴스는 일반 감성의 **부호를 반전**시킨다.

```
if category in ["supply", "harvest", "yield", "production"]:
    price_impact = -1 × general_sentiment
elif category == "substitute_supply":  # 팜유, 유채씨 등
    price_impact = -1 × general_sentiment  # 대체재 공급↑ = 대두유↓
elif category == "competing_crop":      # 옥수수 등 경쟁 작물
    # 작물 회전 효과: 경쟁 작물 풍작은 차기 대두 경작지 축소 압력
    price_impact = -1 × general_sentiment
elif category in ["demand", "policy_biodiesel", "china_imports"]:
    price_impact =  1 × general_sentiment
```

이 규칙층을 LLM/FinBERT 출력 **앞이나 뒤에** 둬서, 범용 모델의 체계적 편향을 명시적으로 교정한다.

#### 3. Few-shot에 역방향 예시를 의도적으로 편성

LLM 프롬프트의 few-shot 예시에서 **역방향 케이스 비중을 50% 이상**으로 구성한다. 일반 예시(수요·정책)만 주면 LLM이 기본값으로 "풍작=긍정"으로 회귀하는 경향이 있다.

```
예시 1: "Record Brazilian harvest" → -0.7 (공급 과잉)
예시 2: "Argentine drought worsens" → +0.8 (공급 감소)
예시 3: "China demand surges" → +0.6 (수요 증가)
예시 4: "Palm oil export ban" → +0.85 (대체재 품귀)
```

#### 4. 도메인 특화 사전/파인튜닝

- **LM 사전 확장**: Loughran-McDonald에 원자재 도메인 단어를 추가. `bumper`, `glut`, `surplus`, `record harvest` → 가격 측면에서 **부정 어휘**로 재정의
- **FinBERT fine-tuning**: 500~1000건의 대두유 도메인 라벨 데이터로 추가 학습
- **골드셋 구성 원칙**: 공급 측 30%, 수요 측 30%, 정책 20%, 매크로 20% 비율로 편성

> [!WARNING] FinBERT 소량 파인튜닝의 한계
> 500~1000건은 FinBERT를 대두유 도메인으로 "옮기기"에는 부족할 수 있다. 과적합·카탈로그적 망각(catastrophic forgetting) 위험이 있으므로, 다음 보완이 필요하다.
> - **데이터 증강**: 동의어 치환, 역번역(back-translation), LLM 기반 paraphrasing으로 2~3배 증강
> - **Layer freezing**: 하위 층은 고정하고 상위 몇 개 층만 업데이트하여 기존 금융 지식 보존
> - **교차 검증**: 시간 기반 split으로 검증 (랜덤 split 금지)
> - **현실적 대안**: 충분한 데이터 확보 전까지는 LLM few-shot을 주력으로 쓰고, FinBERT는 백업·배치 용도로

#### 5. 가격 데이터로 역검증 (Self-correction Loop)

라벨링 후, **실제 가격 반응과의 일치율**을 측정하여 체계적 오류를 잡는다.

```
뉴스 발표 후 +1일 수익률의 부호 vs price_impact_score 부호 일치율
```

- 일치율이 50% 근처면 스코어러가 랜덤과 다름없음 → 프롬프트/모델 재설계
- 특정 카테고리(예: supply)에서만 일치율이 낮다면 해당 카테고리 부호 반전 확인
- 이 지표를 **월 단위로 모니터링**하며 드리프트 감지

### 권장 적용 순서

1. **즉시**: 프롬프트에 "price impact" 명시 + 역방향 few-shot 5개 추가 (방안 1, 3)
2. **단기**: 카테고리 분류 + 부호 반전 규칙층 구축 (방안 2)
3. **중기**: 골드셋 500건 구축 → LM 사전 확장 또는 FinBERT 파인튜닝 (방안 4)
4. **상시**: 가격 데이터 일치율 월간 모니터링 (방안 5)

## 커뮤니티 감성의 역방향 문제 (Community Sentiment Reverse Problem)

전통 뉴스 매체(Reuters, Bloomberg)와는 **별개의 역방향 문제**가 SNS·커뮤니티 데이터에 존재한다. Reddit(r/commodities, r/wallstreetbets), Twitter/X 농업 계정, StockTwits, 중국 Weibo, 브라질 Agrolink 포럼, 국내 종목토론방 등이 대표적 소스다.

### 뉴스 매체 감성 vs 커뮤니티 감성의 차이

| 항목 | 전통 뉴스 | 커뮤니티/SNS |
|------|-----------|-------------|
| 작성 주체 | 전문 기자 | 개인 투자자·농민·트레이더·봇 |
| 사실성 | 검증 거침 | 소문·루머 혼재 |
| 톤 | 중립 지향 | 감정·과장·비꼼 많음 |
| 선행성 | 사후 보도 다수 | **선행·동행 신호 가능성** |
| 편향 방향 | 매체별 일정 | <mark style="background: #FFF3A3A6;">군중심리·역발상 신호</mark> |
| 데이터량 | 적음 | 매우 많음 (노이즈도 큼) |

### 커뮤니티 감성의 3가지 역방향 패턴

#### (1) 콘트라리안(Contrarian) 반전 — 극단적 낙관은 천장 신호

개인 투자자 커뮤니티가 **극단적으로 낙관**할 때가 오히려 가격 고점인 경우가 많다. 행동재무학의 "retail sentiment is a contrarian indicator" 가설.

> [!NOTE] 직관적 이유
> <mark style="background: #FFF3A3A6;">모든 낙관론자가 이미 매수를 완료했다면 추가 매수 여력이 없다.</mark> 신규 매수세가 고갈되면 작은 악재에도 가격이 쉽게 꺾인다. 반대로 모두가 비관하여 팔 사람이 다 팔았다면, 작은 호재에도 반등이 크다. 커뮤니티 감성의 극단값은 "남은 매수/매도 여력의 고갈 신호"로 해석된다.

- 예: WSB에서 "soyoil to the moon" 게시물이 폭증 → 단기 고점 확률↑
- 예: 농민 트위터가 "이번에 대박" 합의 → 이미 포지션 청산 시점

**탐지 방법**:
- 게시물 수 + 평균 감성 Z-score가 동시에 +2σ 초과 → 과열 플래그
- Put/Call ratio, CFTC 투기 포지션과 **동반 극단값**일 때 신뢰도↑

#### (2) 아이러니·비꼼(Sarcasm) 반전 — 표면 감성이 반대

SNS 특유의 반어법, 밈, 이모지 사용이 사전·ML 모델을 속인다.

- "Great, another bumper crop 🙃" → 표면 긍정, 실제 부정
- "Yeah sure, USDA numbers totally reliable 🤡" → 표면 중립, 실제 강한 불신

**해결 방안**:
- **사전 기반/FinBERT 단독 사용 금지** (비꼼에 가장 취약)
- **LLM + 이모지 토큰 보존**: 이모지를 제거하지 말고 입력에 포함
- **문맥 창 확장**: 단일 게시물이 아니라 스레드·댓글 함께 투입
- **역방향 학습셋**: 비꼼 라벨링된 공개 데이터(SARC, iSarcasm 등)로 검증

#### (3) 군중 합의 편향(Herding) — 커뮤니티 내부 에코체임버

한 커뮤니티 안에서 의견이 빠르게 수렴하여 **외부 시장과 괴리**되는 현상. 해당 커뮤니티 감성을 그대로 쓰면 소수 의견 제거로 과대평가된다.

- 예: WSB는 항상 롱 편향, 특정 농민 포럼은 상시 공급 비관
- 결과: 커뮤니티 "평균 감성"은 시장 전체 심리가 아닌 **해당 부족의 편향**

**해결 방안**:
- **커뮤니티별 베이스라인 보정**: `adjusted = raw - community_mean_3m`
- **다중 커뮤니티 평균**: 단일 소스 가중치를 낮추고 여러 커뮤니티 교차 평균
- **이견(dispersion) 피처**: 감성 점수의 분산(variance)이나 엔트로피(entropy, 의견 분포의 불확실성 척도)를 피처로 사용. <mark style="background: #FFF3A3A6;">예시: 어제까지 90%가 강세였는데 오늘 50:50으로 갈라졌다면 dispersion이 급증 → 합의 붕괴 신호</mark>. 이런 변곡점은 종종 추세 전환에 선행한다. 반대로 dispersion이 계속 낮으면 "에코체임버 지속" 상태로 판단

### 커뮤니티 데이터 처리 구체 방안

#### A. 소스별 가중치 재설계

전통 뉴스의 소스 가중치와 **별도 체계**로 관리한다.

| 커뮤니티 | 특징 | weight | 사용 목적 |
|----------|------|--------|-----------|
| StockTwits $ZL | 트레이더 중심 | 0.6 | 단기 심리 |
| Reddit r/commodities | 준전문가 | 0.5 | 이슈 조기 포착 |
| Reddit r/wallstreetbets | 개인 군중 | 0.3 | **콘트라리안 시그널** |
| 농민 Twitter (AgTwitter) | 공급 측 현장 | 0.7 | 작황·날씨 조기 정보 |
| Weibo 농업 | 중국 수요 심리 | 0.6 | 수요국 동향 |
| 국내 종목토론방 | 리테일 | 0.2 | 보조 지표 |

#### B. 봇·스팸 필터링 (필수)

- 계정 생성일, 팔로워/팔로잉 비율, 게시 빈도 이상치로 봇 제거
- 동일 문구 반복(copy-paste) 스팸 제거
- **봇 제거 전후 감성 차이**를 별도로 저장 → 조작 여부 감지

#### C. 피처를 '원값'과 '반전값' 2개로 운영

> [!NOTE] 핵심 설계 팁
> 커뮤니티 감성은 상황에 따라 순방향·역방향이 **둘 다 맞을 수 있다**. 피처를 하나로 고정하지 말고 둘 다 만들어 모델이 선택하게 한다.

```
community_sent_raw       : 원본 감성 평균
community_sent_contra    : 극단값 구간에서 부호 반전
community_sent_dispersion: 이견 수준 (합의 붕괴 감지)
community_volume_z       : 게시량 이상치 (관심 폭증)
```

트리 기반 모델(XGBoost, LightGBM)은 비선형 상호작용을 잡아주므로, **원값과 반전값을 함께 투입**해도 이중 카운팅 문제가 적다.

> [!NOTE] master_daily 통합 방식
> 위 4종 커뮤니티 피처는 `community_` 접두사로 구분하여 `master_daily` 테이블에 **date 키로 조인**한다. 기존 뉴스 감성 피처(`news_sent_*`)와 별도 컬럼으로 유지하여 모델이 "전문 뉴스 vs 커뮤니티" 신호를 구분 학습할 수 있게 한다. 커뮤니티 데이터가 없는 과거 구간은 NaN으로 두고, 모델에서 masking 또는 기간 제한으로 처리.

#### D. 극단값 검증 루프

커뮤니티 감성이 ±2σ를 넘은 날에 대해 **다음 5영업일 수익률**을 추적하여:
- 평균 수익률이 부호 일치 → **모멘텀 신호**
- 평균 수익률이 부호 반대 → **콘트라리안 신호**

카테고리·시기별로 둘 중 어느 체제에 있는지 주기적으로 재확인한다. 이 체제는 시간에 따라 바뀐다는 점이 중요하다.

### 권장 적용 순서 (커뮤니티 감성)

1. **1순위**: 봇·스팸 필터링과 소스별 가중치 체계 구축
2. **2순위**: 원값·반전값·이견·볼륨 4종 피처 동시 생성
3. **3순위**: ±2σ 극단 이벤트 이후 수익률 체제 분석 (모멘텀 vs 콘트라리안)
4. **4순위**: 이모지·비꼼 강건성을 위해 LLM 기반으로 단일화 — 커뮤니티 텍스트는 반어법·밈·이모지·줄임말 비중이 높아 사전 기반(LM, VADER)과 FinBERT 모두 취약하다. 전통 뉴스는 사전+LLM 하이브리드가 비용 효율적이지만, 커뮤니티는 **LLM 단일 체계**가 품질 면에서 유일한 실전 해법이다

> [!NOTE] 체제(Regime) 전환이란
> 같은 시그널(예: 커뮤니티 강세)이 어떤 시기에는 모멘텀(순방향)으로, 다른 시기에는 콘트라리안(역방향)으로 작동하는 현상. 예를 들어 **상승 추세장**에서는 커뮤니티 낙관이 모멘텀 신호로 작동하다가, **과열 국면**에 진입하면 같은 낙관이 반전 신호로 바뀐다. 변동성 수준·거래량·CFTC 포지션 극단값 등으로 현재 체제를 판별한 뒤, 체제별로 피처의 부호 해석을 다르게 해야 한다. 이 체제는 수개월 단위로 전환되므로 **분기마다 재검증**하는 것이 실무 표준이다.
5. **상시**: 커뮤니티별 베이스라인 감성을 월 단위로 재측정하여 에코체임버 보정

> [!WARNING] 대두유 특수성
> 대두유는 개인 투자자 참여도가 주식 대비 낮아 WSB급 군중 신호는 약하지만, **농민·트레이더·중국 수요 측 커뮤니티**가 오히려 선행 정보를 품고 있을 가능성이 높다. "어떤 커뮤니티가 정말로 정보 우위를 가지는가"를 먼저 맵핑하는 것이 선행 작업이다.

> [!NOTE] 뉴스 없는 날
> 0으로 채움(중립 가정) / forward fill(지속 가정) / NaN 유지(트리 모델). 설계 선택.

## 검증 방법
1. 상관관계 분석 (감성 vs 다음날 수익률)
2. 이벤트 스터디 (극단값 발생 전후)
3. 피처 중요도
4. Ablation test (감성 피처 유무에 따른 성능 비교)
